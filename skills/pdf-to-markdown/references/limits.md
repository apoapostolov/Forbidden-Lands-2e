# Repair Limits

Some problems should not be repaired automatically.

## Stop and verify

- the source order contradicts the markdown order
- a table cannot be reconstructed confidently
- a block seems owned by the wrong heading
- the text could change meaning if repaired blindly

## Keep and note

If you cannot repair a block without guessing, keep the best recovered version and note the ambiguity.

## Do not

- invent missing cells
- invent missing prose
- reorder sections for style alone
- overfit a fix to one chapter if the pattern is not general
