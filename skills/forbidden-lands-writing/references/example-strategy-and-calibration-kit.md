## When Examples Are Necessary

Examples earn their space when they clarify:

- interacting small rules
- timing or order of operations
- hard-to-see consequences
- player-facing procedure inside a scene

Examples are usually not needed when:

- one sentence already resolves the rule
- the example merely repeats the rule
- the example is longer than the confusion it solves

## Example Construction Rules

Good examples in this manuscript should:

1. name a character
2. establish a specific situation
3. state the roll or trigger
4. show the result
5. show the consequence in play

### Multi-rule example pattern

When several small rules interact:

- establish the scene clearly
- do not explain every rule first
- move through the scene in the real order of operations
- let the example teach by sequencing

### Tone rule

The example should still sound like play in the world, not like a textbook problem.

## Scenario-Based Test Set

Use these as writing calibration tasks.

### Test 1: Rewrite a gear rule

Goal:

- make an equipment explanation sound native to `10-gear.md`

Must show:

- concrete object identity
- practical use
- brief, clean procedure

### Test 2: Explain a healing procedure

Goal:

- teach an interaction between recovery, care, and injury honestly

Must show:

- no clinical drift
- direct rule hooks
- no proposal rationale leakage

### Test 3: Draft a chapter intro

Goal:

- bridge atmosphere into subsystem purpose

Must show:

- world truth first
- player implication second
- no abrupt style rupture

### Test 4: Revise a proposal paragraph for promotion

Goal:

- turn design-stage prose into manuscript-native prose

Must show:

- removal of editorial scaffolding
- tighter diction
- clearer paragraph job

## Revision Rubric

Score each draft on:

### Voice fidelity

- does it sound like it belongs beside the current manuscript

### Structural fit

- does the paragraph job match the section's purpose

### Clarity

- can the reader act on it without extra explanation

### Terminology integrity

- does it reuse existing game terms correctly

### Example necessity

- are examples present only where they earn space

### Table usability

- can the GM or player use it under live-play pressure

## Before-And-After Calibration Guidance

When storing rewrite examples, capture:

1. original text
2. revised text
3. what changed in diction
4. what changed in structure
5. what changed in rule clarity

The point is not only to show a better line.
It is to show why the new line is better in manuscript terms.
