# Proposals AGENTS

## Purpose

This folder contains design-stage documents for rules, rewrites, and system experiments.

These files are not automatically canonical. They are meant to:

- frame a problem
- propose a rule
- identify where it would land in the manuscript
- preserve design reasoning before integration

## Proposal Writing Rules

- Write clearly and concretely.
- Prefer tables, examples, and actual rule language over abstract discussion.
- Explain downstream effects.
- Keep proposal rationale in proposals, not in the final manuscript.
- Name files descriptively.

## Canon Rule

Only `corebook/` is canonical in this public repo.

If a proposal is promoted:

1. integrate it into `corebook/`
2. update relevant changelog entries
3. leave the proposal as design history unless there is a reason to remove it

## Style Rule

Even proposal docs should sound like thoughtful tabletop design work, not like software tickets or AI filler.
